# Source data for Assignment 2.3

Dummy source files for five consecutive business days (1 to 5 Nov 2026), generated by `tools/generate_source_files.py`. Items and stores are a subset of the Northline Retail reference data used in Assignments 2.1 and 2.2 (40 items from 8 departments, 12 stores in all 4 areas, including the Canadian store 1137).

The generator uses a fixed random seed, so running it again produces identical files.

## Files

Four files per day, named with the business date (`YYYYMMDD`):

| File | Grain | Feeds |
|---|---|---|
| `item_master_YYYYMMDD.csv` | One row per item (daily snapshot) | `DIM_ITEM`, `DIM_SUBCATG`, `DIM_CATG` |
| `store_master_YYYYMMDD.csv` | One row per store (snapshot, sent with every daily delivery) | `DIM_LOCN`, `DIM_DISTRICT`, `DIM_REGN`, `DIM_AREA` |
| `pos_sales_YYYYMMDD.csv` | One row per sales transaction line | `FCT_SALES` |
| `inventory_snapshot_YYYYMMDD.csv` | One row per item and store (daily position) | `FCT_INVENTORY` |

The slides describe the store master as a weekly snapshot. Because the sensor waits for all four files every day, a store snapshot is delivered with every daily set; it only changes when a store changes.

## Columns

| File | Columns |
|---|---|
| item_master | `item_id`, `item_name`, `brand_name`, `subclass_id`, `subclass_name`, `dept_id`, `dept_name`, `unit_cost`, `unit_retail`, `status` |
| store_master | `store_id`, `store_name`, `store_type`, `district_id`, `district_name`, `region_id`, `region_name`, `area_id`, `area_name`, `country`, `city`, `currency_code`, `open_date`, `close_date` |
| pos_sales | `transaction_id`, `line_number`, `business_date`, `store_id`, `item_id`, `quantity`, `unit_price`, `discount_amount`, `net_amount`, `currency_code` |
| inventory_snapshot | `snapshot_date`, `store_id`, `item_id`, `on_hand_qty`, `unit_cost` |

## Messiness on every day (must be cleaned, not rejected)

| Issue | Example | Expected handling in Silver |
|---|---|---|
| Store code formats | `1101`, `01101`, `NL-01101` | Conform to `1101` |
| Mixed date formats | `2026-11-03` and `11/3/2026` | Parse both |
| Currency spellings | `USD`, `usd`, `US$`; `CAD` for store 1137 | `USD` / `CAD` |
| Spaces around item ids | `" 10000684 "` | Trim |
| Spaces and case in names | `"  Red Barn ..."`, `SUPPLIES` | Trim; compare case-insensitively for change detection |
| Double spaces in store names | `Northline Boston  #1104` | Collapse to one space |
| Negative stock on hand | `on_hand_qty = -4` | Keep (real RMS condition) |

## Inventory

About 20% of item and store balances change each day; the rest stay the same. In `FCT_INVENTORY` only changed balances create a new row, and the previous row is closed (`EFF_END_DT`), not deleted.
